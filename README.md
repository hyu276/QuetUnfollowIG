# QuetUnfollowIG

Local-first Instagram follower/following snapshot tracker with a Next.js live validation console.

## Live deployment

Production test console: https://quet-unfollow-ig.vercel.app

The current production deployment was built successfully with Next.js 16.3.2, passed TypeScript checking, reached Vercel `READY`, and returns HTTP 200.

The repository contains two surfaces that use the same crawler:

1. A Chrome/Chromium Manifest V3 extension that is allowed to use the Instagram session already logged in on `instagram.com`.
2. A Next.js website that acts only as a realtime control and validation console. It sends crawl commands to the extension through a paired browser bridge and never receives the Instagram cookie itself.

## Architecture

A normal hosted website cannot directly reuse the authenticated Instagram session from another tab because browser origin isolation prevents one site from reading another site's cookies/session. For that reason, the privileged GET requests remain inside the extension.

The live website communicates with `web-bridge.js`, which is injected only on Vercel preview/production hosts and localhost. Every web request must also contain a random 36-character pairing key generated by the extension. Rotating that key immediately invalidates the old website pairing.

Data flow:

`Next.js page -> window.postMessage -> web-bridge.js -> extension service worker -> instagram.com -> extension storage -> paired response -> Next.js UI`

There is no Next.js API route in this project and no follower/following payload is POSTed to Vercel.

## What the extension tracks

- Lost followers: present in the baseline/previous Followers list but absent now.
- Accounts you unfollowed: present in the baseline/previous Following list but absent now.
- New followers.
- Newly followed accounts.
- Snapshot history, search, baseline reset, JSON backup export/import.

Comparisons use Instagram numeric user IDs when available, so username changes do not create false positives. A missing account can also mean deactivation, deletion, blocking, or an Instagram-side data inconsistency; the app reports observed list differences rather than claiming intent.

## What the live website validates

The Next.js test console is intentionally diagnostic. During a real crawl it shows:

- Whether the extension bridge is detected.
- Whether the Instagram session is detected.
- Realtime Followers/Following page number.
- Number of accounts received after every page.
- Per-page request latency.
- Whether another pagination page exists.
- Total crawl duration.
- Final Followers and Following counts.
- Duplicate-ID checks.
- Count-vs-array integrity checks.
- Baseline presence.
- Baseline-to-latest follower/following differences.
- Lightweight snapshot history.

The website receives only the baseline and latest user arrays plus history summaries. It does not copy every historical user array over the browser bridge.

## Privacy and permissions

- No password prompt.
- No analytics.
- No remote database.
- No follow/unfollow automation.
- Instagram requests are GET-only.
- Instagram cookies stay inside the extension context.
- Snapshot data is stored in `chrome.storage.local`.
- The bridge requires a pairing key before it can return status or start a crawl.
- Content-script hosts are restricted to `*.vercel.app`, `localhost`, and `127.0.0.1` for the test console.

Do not share the pairing key. If it is exposed, click **Tạo pairing key mới** in the extension popup.

## Install the extension

1. Download or clone this repository.
2. Open `chrome://extensions` in Chrome/Edge/Brave desktop.
3. Enable **Developer mode**.
4. Choose **Load unpacked** and select this repository folder.
5. Open Instagram in the same browser and make sure you are logged in.
6. Click the extension. Confirm that it displays an Instagram account ID and a pairing key.
7. The first successful crawl automatically becomes the baseline.

Whenever you pull a newer commit, click **Reload** on the extension card in `chrome://extensions` before testing the website again.

## Test with the production website

1. Load/reload the extension from this repository in `chrome://extensions`.
2. Make sure Instagram is logged in in the same Chromium browser.
3. Open `https://quet-unfollow-ig.vercel.app`.
4. Open the extension popup and copy the pairing key.
5. Paste it into the website and click **Connect**.
6. The bridge indicator should turn green and the Instagram session should show **Detected**.
7. Click **Run live crawl**.
8. Watch Followers and Following pagination, account counts, page latency, and `Next page` in realtime.

If the bridge indicator stays red, reload the extension and then reload the webpage.

## Run the live website locally

```bash
npm install
npm run dev
```

Open `http://localhost:3000`, copy the pairing key from the extension popup, paste it into the website, and click **Connect**.

## Deploy your own Vercel copy

1. In Vercel choose **Add New -> Project**.
2. Import `hyu276/QuetUnfollowIG` from GitHub.
3. Framework preset should be detected as **Next.js**.
4. Keep the repository root as the Root Directory.
5. No environment variables are required.
6. Deploy.
7. Open the generated `*.vercel.app` URL in the same Chromium browser where the extension is loaded.
8. Paste the pairing key and click **Connect**.

The extension manifest already permits `https://*.vercel.app/*`, so both preview and production deployment URLs can be used for testing. If you later use a custom domain, add that exact domain to both `host_permissions` and the `content_scripts.matches` list in `manifest.json`.

## Recommended validation run

For the first test, leave the Instagram Followers/Following lists unchanged while crawling.

A healthy crawl should end with:

- A final Followers page where **Next page = no**.
- A final Following page where **Next page = no**.
- Snapshot integrity score **6/6**.
- `count === array length` for both lists.
- Unique-ID count equal to array length for both lists.
- A non-empty Instagram numeric account ID.
- A stored baseline after the first successful run.

Then deliberately follow or unfollow one known test account and run a second crawl. The baseline diff should identify that numeric user ID in the expected category.

## Rate limits and endpoint stability

Instagram's internal web endpoints are undocumented and can change without notice. The crawler currently paginates the internal friendship-list endpoints with `next_max_id` and adds a randomized delay between pages. A `401/403` is surfaced as a session/authorization error and a `429` is surfaced as rate limiting.

Do not repeatedly hammer the crawl button. Use a conservative testing cadence.
